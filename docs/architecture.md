# Architecture

Next.js App Router site + Payload CMS in one app. All source lives in `src/`.

## Layout

- `src/app/(site)/[locale]/` - public site: home, `/posts`, `/posts/[slug]`. The layout renders `<html lang>`, Header and Footer.
- `src/app/sitemap.ts`, `robots.ts`, `llms.txt/route.ts` - crawler and answer-engine files, outside the locale segment.
- `src/proxy.ts` - locale routing (see i18n).
- `src/app/(payload)/` - Payload admin (`/admin`), REST (`/api/[...slug]`) and GraphQL (`/api/graphql`). Generated by Payload; don't hand-edit.
- `src/collections/` - Payload collection configs.
- `src/components/` - UI components. The home page is built from `components/profile/` (profile card, milestone row, featured project, tabs, rails).
- `src/lib/` - `profile.ts` (career facts: teams, projects, stack, milestones), `github.ts` (GitHub activity), `i18n.ts` (server-side dictionaries), `locales.ts` (locale list, URL helpers), `posts.ts` (server-side REST reads), `structured-data.ts` (JSON-LD), `site.ts` (origin URL), `fetcher.ts` (SWR fetcher).

## Collections

- **Posts** - title, excerpt, content (Lexical richText) are localized (en/pt-BR). `slug` unique, auto-generated from title in a `beforeChange` hook. `status` draft/published, `publishedAt`, `coverImage` -> media, `category` -> categories. Anonymous users read only published posts.
- **Categories** - name, description localized; `slug` unique. Public read.
- **Media** - images only, `alt` required, public read. Stored on Supabase Storage through the S3 adapter (`payload.config.ts`).
- **Users** - Payload auth (JWT). `role` admin/editor (default editor) saved to JWT. Only admins create/delete users or change roles.

## Data flow

- Home (`(site)/page.tsx`) is a server component with `revalidate = 3600`. It fetches public repos from the GitHub REST API and, when `GITHUB_TOKEN` is set, a private contribution count from the GraphQL API (`lib/github.ts`). Profile content comes from `lib/profile.ts`, not the CMS.
- Post page (`posts/[slug]/page.tsx`) is a server component that fetches `/api/posts?where[slug][equals]=...&depth=1` with `revalidate: 60` and calls `notFound()` on miss.
- The posts list (`[locale]/posts/page.tsx`, ISR 60s) fetches posts and categories server-side through `lib/posts.ts`; `PostsPageContent.tsx` only filters by category in the browser. `lib/posts.ts` goes over HTTP because pages prerender at build time without database access; on failure it returns null and the page shows an error state until the next revalidation.
- The home posts panel (`profile/PostsPanel.tsx`) fetches client-side with SWR, since the home page prerenders at build time. `fetcher` throws on non-2xx so SWR shows an error state.
- `locale` is passed to the posts API, but `payload.config.ts` has no `localization` block, so localized fields hold a single value for now.
- Lexical JSON is rendered by a custom recursive renderer in `PostPageContent.tsx` (format bitmask: `format & 1` = bold, etc.).

## Theme

An inline script in the `(site)` layout head reads `localStorage.theme` before paint. It adds `dark` to `<html>` (theme=dark, or system preference). `globals.css` defines the color tokens and overrides them on `.dark`; see `DESIGN.md`. `ThemeToggle` is loaded with `next/dynamic`.

## i18n

The locale is part of the URL. Pages live under `app/(site)/[locale]` and prerender for `en` and `pt-BR`. English is served unprefixed: `src/proxy.ts` rewrites `/x` to `/en/x` and 308-redirects `/en/x` back to `/x`. pt-BR keeps its `/pt-BR` prefix. `LanguageToggle` links to the same page in the other locale.

Server components call `getTranslator(locale)` from `lib/i18n.ts` (keys typed from the `en` dictionary). Client components (`ProfileTabsView`, `FeaturedCarousel`, `PostsPanel`, `PostsPageContent`, `HeaderActions`) receive resolved strings and data as props, so neither the dictionaries nor `lib/profile.ts` reach the browser bundle. Localized profile data uses `Record<Locale, string>` and the `pick()` helper in `lib/profile.ts`.

## SEO

- Every page sets `alternates.canonical` and hreflang `languages` (en, pt-BR, x-default) from `languageAlternates()`; `metadataBase` comes from `NEXT_PUBLIC_SERVER_URL`. Open Graph fields shared by all pages come from `baseOpenGraph()`, because Next replaces a parent's `openGraph` instead of merging it.
- JSON-LD (`lib/structured-data.ts`): `WebSite`, `ProfilePage`, `Person` and `FAQPage` on the home page, `BlogPosting` on posts. Built only from `lib/profile.ts` and CMS data.
- `/sitemap.xml` lists home and posts index in both locales, plus every published post when the CMS answers. `/llms.txt` is a plain-text profile for LLMs built from `lib/profile.ts`.
