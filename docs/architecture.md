# Architecture

Next.js App Router site + Payload CMS in one app. All source lives in `src/`.

## Layout

- `src/app/(site)/` - public site: home, `/posts`, `/posts/[slug]`. `SiteWrapper.tsx` composes Header, Footer and `LanguageProvider`.
- `src/app/(payload)/` - Payload admin (`/admin`), REST (`/api/[...slug]`) and GraphQL (`/api/graphql`). Generated by Payload; don't hand-edit.
- `src/collections/` - Payload collection configs.
- `src/components/` - UI components. The home page is built from `components/profile/` (profile card, milestone row, featured project, tabs, rails).
- `src/lib/` - `profile.ts` (career facts: teams, projects, stack, milestones), `github.ts` (GitHub activity), `i18n.tsx` (locale context), `fetcher.ts` (SWR fetcher).

## Collections

- **Posts** - title, excerpt, content (Lexical richText) are localized (en/pt-BR). `slug` unique, auto-generated from title in a `beforeChange` hook. `status` draft/published, `publishedAt`, `coverImage` -> media, `category` -> categories. Anonymous users read only published posts.
- **Categories** - name, description localized; `slug` unique. Public read.
- **Media** - images only, `alt` required, public read. Stored on Supabase Storage through the S3 adapter (`payload.config.ts`).
- **Users** - Payload auth (JWT). `role` admin/editor (default editor) saved to JWT. Only admins create/delete users or change roles.

## Data flow

- Home (`(site)/page.tsx`) is a server component with `revalidate = 3600`. It fetches public repos from the GitHub REST API and, when `GITHUB_TOKEN` is set, a private contribution count from the GraphQL API (`lib/github.ts`). Profile content comes from `lib/profile.ts`, not the CMS.
- Post page (`posts/[slug]/page.tsx`) is a server component that fetches `/api/posts?where[slug][equals]=...&depth=1` with `revalidate: 60` and calls `notFound()` on miss.
- The posts list (`PostsPageContent.tsx`) and the home posts panel (`ProfilePanels.tsx`) fetch client-side with SWR, passing `&locale=`. `fetcher` throws on non-2xx so SWR shows an error state.
- Lexical JSON is rendered by a custom recursive renderer in `PostPageContent.tsx` (format bitmask: `format & 1` = bold, etc.).

## Theme

An inline script in the `(site)` layout head reads `localStorage.theme` before paint. It adds `dark` to `<html>` (theme=dark, or system preference). `globals.css` defines the color tokens and overrides them on `.dark`; see `DESIGN.md`. `ThemeToggle` is loaded with `next/dynamic`.

## i18n

Client-side only. `LanguageProvider` stores the locale in localStorage and keeps `<html lang>` in sync; components call `t()` from `useLanguage()`. Translation keys are typed from the `en` dictionary. Localized profile data uses `Record<Locale, string>` and the `pick()` helper in `lib/profile.ts`.
